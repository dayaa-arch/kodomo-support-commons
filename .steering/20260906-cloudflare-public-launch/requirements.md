# Cloudflare 公開準備と運用基盤 — 要求定義

## 背景

現在のアプリケーションは、静的データを使った検索・詳細表示・緊急相談導線まで実装され、lint、型検査、単体テスト、production build、主要ブラウザ導線は通っている。一方で、公開情報の鮮度監査、データ利用条件、公開ポリシー、継続的検証、Cloudflare 向け配信設定が未整備であり、このまま恒常公開するのは適切ではない。

本変更では、Cloudflare Pages を配信先とする公開ベータ版として、安全に運用を開始できる状態まで仕上げる。

## 目的

- 子ども・保護者・支援者が、誤解を招きにくい最新の案内から公的・公式窓口へ移動できる。
- データの由来、更新日、免責、プライバシー方針を利用者と保守者の双方が確認できる。
- GitHub への変更時と定期実行時に、品質、データ整合性、リンク切れ、情報鮮度を検査できる。
- Cloudflare Pages で静的コンテンツを配信し、個人を識別しない2種類の利用イベントだけを任意に収集できる。
- 独自ドメイン取得後に、コード変更を伴わず公開 URL と検索エンジン公開設定を切り替えられる。

## 対象範囲

### 1. 掲載情報の是正

- チャイルドラインの受付案内に年末年始の休止日を反映する。
- TLS 証明書が不正な「児童家庭支援センター みたけ」の公式 URL を、有効な運営法人の公式ページへ差し替える。
- 緊急相談先について、表示文言、電話番号、受付時間、公式 URL、最終確認日を同じデータモデルで管理する。
- 公開前に緊急相談先を公式情報で再確認し、確認日を更新する。

### 2. データ品質と監査

- seed JSON の日付、URL、件数、区コード・区名、ID、重複、参照元カタログとの対応を機械検証する。
- 参照元タイトルは `provider_type` ではなく、各レコードの `source_url` に対応するカタログ項目から解決する。
- 施設・相談先の公式 URL と参照元 URL を検査するリンク監査コマンドを追加する。
- 情報鮮度は、緊急相談先を30日、施設情報を90日の基準で検査する。期限超過は公開ビルドまたは定期監査で検知できるようにする。
- リンク監査はタイムアウトと限定的な再試行を持ち、TLS エラーと恒常的な 4xx/5xx を失敗として扱う。

### 3. プライバシーを守る最小分析

- 計測対象を `facility_detail_view` と `official_site_click` の2イベントに限定する。
- 送信内容をイベント名と施設 slug に限定し、氏名、連絡先、自由入力、Cookie、端末 ID、セッション ID、IP アドレス、User-Agent をアプリケーションの分析データとして保存しない。
- Cloudflare Pages Functions で入力を厳格に検証し、Cloudflare Analytics Engine に集計用データだけを書き込む。
- 計測失敗が検索、詳細閲覧、公式サイトへの遷移を妨げない。
- ローカル開発と未設定環境では計測を無効にできる。
- Cloudflare Web Analytics は、上記2イベント以外の閲覧指標を収集するため初期公開では有効化しない。

### 4. Cloudflare Pages 配信

- Next.js の Static Export を用い、Cloudflare Pages が `out` ディレクトリを配信できるようにする。
- Node.js 24.18.0 をローカル、CI、Cloudflare build の基準バージョンとして文書化する。
- 本番 URL とインデックス許可を環境変数で切り替え、canonical URL、robots、sitemap を生成する。
- セキュリティヘッダーを Cloudflare Pages 用設定として配信成果物に含める。
- 独自ドメイン未決定の間は Pages のプレビュー URL で検証し、購入後に apex ドメインを Pages に接続できる構成とする。

### 5. 公開ポリシーとリポジトリ整備

- サイト上にプライバシーポリシー、利用上の注意・免責、データの出典と更新方針を掲載し、フッターから到達できるようにする。
- Cloudflare による配信・最小分析と、外部 Google フォームへ移動する場合の扱いを明記する。
- コードには MIT License を付与する。
- 施設・相談先データには一律の再利用許諾を宣言せず、出典ごとの権利・利用条件に従う旨を `DATA_NOTICE.md` とサイトに明記する。
- README の「オープンデータ」という表現は、権利確認済みと誤認されない記述へ修正する。
- `SECURITY.md` と `CONTRIBUTING.md` を用意し、脆弱性報告とデータ訂正の窓口・手順を示す。

### 6. 継続的品質保証

- Pull Request と既定ブランチへの push で、依存関係の固定インストール、lint、型検査、テスト、データ検証、静的 build を実行する。
- 定期ワークフローでリンク監査と鮮度監査を実行し、失敗を GitHub Actions で確認できるようにする。
- 主要導線、キーボード操作、狭幅・広幅表示、アクセシビリティツリー、404、ポリシーページを公開前に確認する。
- Cloudflare Pages のプレビュー配信で、静的ページと分析エンドポイントの両方を検証する。

## 受け入れ条件

1. `npm run lint`、`npm run typecheck`、`npm test`、データ監査、リンク監査、Cloudflare 用 build が成功する。
2. `out` にトップ、検索、全施設詳細、ポリシー、robots、sitemap、セキュリティヘッダーが生成される。
3. 既知の誤記と無効な TLS URL が解消され、緊急相談先の確認日が公開時点の公式情報に基づく。
4. 不正な分析イベントや未知の slug は保存されず、正しい2イベントだけが匿名データとして受理される。
5. 分析機能が停止していても、公式サイトへのリンクは正常に開く。
6. 利用者が各施設の出典・最終確認日と、サイト全体のデータ方針・免責・プライバシー方針を確認できる。
7. GitHub Actions が通常の品質検査と定期監査を実行できる。
8. Cloudflare Pages のプレビュー URL で主要導線とエラー応答を確認できる。
9. 独自ドメインと検索エンジン公開は、所有者が最終判断するまで無効または保留できる。

## 対象外

- 管理画面、ユーザー登録、問い合わせ内容の保存、施設事業者によるセルフ更新機能
- 全84施設からの掲載許諾・運営者確認の取得
- Cloudflare Web Analytics や広告・行動追跡ツールの導入
- サイト全体のデザイン刷新
- この変更時点でのドメイン名決定・有料購入

## 公開上の前提と残余リスク

- 本公開は、掲載内容を医療・福祉・法的助言として保証するものではなく、必ず公式サイト・窓口で最新情報を確認する導線を維持する。
- 通常の自治体 Web ページや第三者サイトの情報には個別の権利条件がある。データを無条件にオープンライセンス扱いせず、出典表示と訂正受付を行う。
- ドメイン購入、Cloudflare と GitHub の接続権限付与、公開切り替えは外部状態を変更するため、実行直前に対象を示して確認する。
