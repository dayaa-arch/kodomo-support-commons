# UI の文言・アイコン・重複の改善 — 要求

> UI レビュー（2026-07-29）で挙がった指摘のうち、項目2〜15 を対象とする。項目1（電話番号の `tel:` リンク化）は Step 3 以降で対応。

## 1. 目的

利用者が「迷わず・誤解なく・必要な情報にたどり着ける」状態にする。機能追加ではなく、既存画面の**表現と情報設計**の改善に絞る。

## 3. ユーザーストーリー

- **US-1**: 利用者として、緊急時の案内では「準備中」ではなく、いま実際に使える連絡先を知りたい。
- **US-2**: 利用者として、同じ情報が1ページで何度も繰り返されず、短時間で施設を比較したい。
- **US-3**: 利用者として、検索結果の各施設について「情報がありません」ではなく、対象年齢など判断材料になる事実を見たい。
- **US-4**: 利用者として、選択肢のアイコンから内容を直感的に読み取りたい。同じ絵が別の意味で出てこないでほしい。
- **US-5**: 利用者として、画面ごとに言い回しが変わらず、一貫した言葉で案内されたい。

## 4. 受け入れ条件

- **AC-1**: 緊急セクションに「モック」「Step 3」「準備中」などの開発者向け文言が存在しない。
- **AC-2**: 詳細ページで、特徴タグに出した項目が下の表に重複して現れない。
- **AC-3**: 検索結果カードで、同じ情報（費用など）が2箇所に現れない。
- **AC-4**: 検索結果カードの説明行が「公式サイトで確認してください」一色にならず、実在する情報（対象年齢など）が表示される。概要が登録済みならそれを優先する。
- **AC-5**: 詳細ページで「公式サイトで確認してください」の表示が1箇所にまとまり、未掲載の項目名が明示される（**空欄にはしない**）。
- **AC-6**: モバイルで「条件を変更する」の導線が1つだけになる。
- **AC-7**: Q1 と Q2 の選択肢アイコンが、「その他」を除いて重複しない。
- **AC-8**: `sparkles` がどこにも使われていない。`shield-check` が安全・確認状況以外の意味で使われていない。
- **AC-9**: 「気になること」「相談したいこと」の表現が無くなり、「困っていること」に統一されている。
- **AC-10**: 「費用は要確認」の表現が無くなり、「公式サイトで確認してください」に統一されている。
- **AC-11**: Q3 の説明に市全域の窓口が含まれる。Q1 の見出し上と質問の視点が揃っている。
- **AC-12**: トップ見出しが日本語として自然につながる。
- **AC-13**: lint / typecheck / test / build がすべて成功する。
- **AC-14**: 未掲載項目の抽出ロジックに単体テストがある。

## 5. 制約事項

- **推測で埋めない原則を維持**する。未掲載であることは引き続き利用者に明示する（表示方法を変えるだけ）。
- **ランキングを持ち込まない**。タグの取捨選択は「事実が確認できたか」のみで判断し、優劣を示さない。
- プライバシー要件（検索条件を URL/Storage に出さない）に変更を加えない。
- 緊急相談先の**データ駆動化・Google フォーム・アクセス解析は Step 3 のまま**（本作業では文言のみ）。
- 施設データ（`data/seed/*.json`）は変更しない。

## 6. 項目5 についての補足（両立方針）

概要（`summary`）は正本データに存在せず、運営者が84施設を巡回して入力する予定。本作業では**入力を待たずに読める状態**にしつつ、入力後は自然に反映されるようにする。

- カードの説明行: `summary` があればそれを表示し、無ければ対象年齢（`whoCanUse`）を表示。どちらも無ければ行自体を出さない。
- 後日 `summary` が入力されれば、コード変更なしで概要が優先表示される。
